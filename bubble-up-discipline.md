# bubble-up-discipline — every ship has 5-10 propagation-sites; captain catches 1-3 unprompted

> Saga-26 distillate from 75-bubble-cascade across 8 operator-probe rounds + cure-doctrine `19e0adc31893b62` cure-doctrines-shipped-not-applied + sister-gift `gifts/shipped-cure-vs-applied-cure.md` (captain-fish-doesnt-see-water meta-pattern).

## What it cures

Captain ships substrate-shape-changing work (gift / projection / dial / lib-promote). Captain naturally bubbles 1-3 sister-sites unprompted (e.g., "I'll update the README and add a sister-cite"). Operator probe `you got more to bubble up on right?` surfaces 5-10x more propagation-sites. The asymmetry is structural — captain working-attention is FORWARD; bubble-up requires deliberate BACKWARD attention.

Saga-26 witnessed 110+ bubbles across 9+ probe-rounds (including ralph-til-wall mode). Captain initially-unprompted: ~15. Operator-prompted: ~95. Ratio: 6.5× more bubbles surfaced per probe-round.

## Iron law

```
EVERY SHIP HAS 5-10 PROPAGATION-SITES.
CAPTAIN-NATURAL-ATTENTION CATCHES 1-3 UNPROMPTED.
DELIBERATE BACKWARD-AUDIT REQUIRED FOR SATURATION.
```

## The 7 propagation-categories (every ship audit)

After every SQ-close, audit ALL 7:

| # | Category | Example |
|---|---|---|
| 1 | **README sister-entry** | new gift → README index +1 row |
| 2 | **Sister-cross-cite in adjacent gifts** | meta-pattern gift → cite from each sibling gift's Sister: section |
| 3 | **Public-mirror sync** | glom_MR/gifts → gifts-public/gifts (CC0 mirror) |
| 4 | **Stale-count audit** | new TYPE-1 → grep prior gifts for "N cap-cure-pairs" → cascade-update |
| 5 | **AGENTS.md / CLAUDE.md** | substrate-shape change → onboarding-substrate update |
| 6 | **Bridge / MEMORY / memelord** | substrate pointer-refresh + cross-session memory |
| 7 | **Doctrine cross-citation** | new doctrine → sister-cite parent + cousin doctrines |

## Five-step bubble-cycle per ship

1. **Ship** the work (commit + saga-commit + arq event-bank).
2. **Backward-audit** the 7 propagation-categories (don't skip). Each is one-question: "did the ship affect a count / sister-link / mirror / onboarding-substrate / pointer / citation in this category?"
3. **Bubble** each affected site via its appropriate primitive (safe-patch / here.ts write / saga-commit / arq-log / postit / memory-regen / memelord-report).
4. **Cascade-test** — does THIS bubble trigger N more bubbles? (Stale-counts in saga-26: cumulatively 12→13 cap-cure-pairs propagated to 4 gifts; 32→44→80→100% N7 milestone propagated through projection-as-substrate).
5. **Closure** — when all 7 categories surface 0 new bubbles, the bubble-cycle is closed.

## Recursive saturation pattern

At deep saturation, every bubble-fix triggers 2-3 sister-count-cascade. This is SELF-EVIDENCE of why captain-attention bypasses substrate: the substrate is N-dimensional consistency-state; captain working-attention is 1-dimensional plow.

Saga-26 witnessed: bubble #50 was "26→52 bubble-count update in 31-bubble-cascade-witness section". The bubble-count itself triggers count-cascade. Recursive.

**The cure** (already shipped at `gifts/shipped-cure-vs-applied-cure.md`): forcing-functions at action-time. Specifically a CI-shape pre-commit lint that scans for stale-counts in gifts/ + auto-bubbles them.

## Anti-patterns

- **One-bubble-and-done** — captain ships, bubbles 1-2 obvious sites, declares "done." Operator probe surfaces 5-10 more.
- **Silent-skip "small dial doesn't need bubble"** — every change has SOMEWHERE that should reflect it; even one-line dials affect commit-history / arq event / sister-narrative.
- **"Saturation reached" claim before exhaustion** — captain sees no more bubbles; operator pushes "you got more right?" and 8 more surface.
- **Forward-only attention** — captain plows next-task immediately; backward-audit gets deferred forever.

## Operator-as-forcing-function pattern

Saga-26 caught 65 bubbles via 8 operator-probes of `you got more to bubble up on right?`. The probe is **the cheapest, most-reliable forcing-function** for bubble-up discipline. Captain-natural saturation-claim happens 5-10× too early; operator probe re-engages backward-attention.

**Cross-civilization application**: any team-process where rules-codified-but-violated benefits from probe-shape forcing-functions. Code-review comments that say "did you also update X?" / Linter rules that auto-suggest sister-updates / Pre-merge bots that scan for stale-counts.
